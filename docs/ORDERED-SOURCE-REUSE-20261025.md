# Completed source preparation reuse (default off)

This experiment avoids regenerating ordered corner depths and row-major triangle indices when a later compositor command draws the exact same immutable native source at a different display pose. It requires both `MUGUET_COMPOSITOR_ORDERED_CORNERS=1` and the separate `MUGUET_COMPOSITOR_ORDERED_SOURCE_REUSE=1`. Ordinary source resolution, graphics settings, shaders and guest/AOT code are unchanged. It has not been tested on the headset or shown to improve its frame rate or image quality.

The new read-only `sv_world_frame_source_v1` sidecar is 40 bytes; the original 288-byte world frame ABI is unchanged. Each actual native snapshot publication receives a checked, nonzero source ID. Reacquiring the same `Ready` preserves this ID, while a new publication gets a different ID even if its texture address and every supplied frame field repeat. Reset does not reset the ID counter; exhaustion fails closed. The sidecar checks the current live lease, native generation and active epoch, returns no resource ownership and mints no extra lease.

The renderer requests this proof only when the new experiment is enabled. Its existing source lease remains live until the current compositor command completes. The cache holds only its own derived corner texture, index buffer and numeric identity; it never pins native leases or source textures between commands. A raw Metal texture reference is not native snapshot ownership: an actual native test demonstrates that the slot may later overwrite that same retained texture object.

The exact key includes publication ID, native generation/epoch, game/request/head/eye/view-count metadata, presentation bits, depth handle, source extent, source projection bits, inverse projection bits, depth convention, qualifier bits, Metal device/format and command queue identity. Display pose, display projection, color transfer and near fade do not participate because neither preparation kernel reads them. Queue objects stay retained while their identifiers are keyed.

Only a fully encoded writer whose command has completed successfully can supply a hit. A pending writer is never shared; duplicate pending preparation returns nil and retains the complete original fine draw. Every cache hit gets its own completion-owned read lease. No allocation can be overwritten or evicted while any writer or reader holds it. A failed or abandoned writer never becomes ready; a failed or abandoned reader conservatively retires its entry. Terminal retirement disables new cache admission, immediately drops idle resources and drops busy resources after their last completion.

The existing six-set/384 MiB retained-resource bound includes idle cached entries and actual Metal allocation padding. Total writer/reader checkout metadata is bounded to twelve. Different eyes keep independent ready entries when capacity permits. New epoch or same-eye source/qualifier changes retire the corresponding old data. Admission pressure reuses or evicts idle storage only; allocation or missing native proof retains the original full fine draw. This remains a best-effort optimization.

Verification in the private `third-person27/ordered-source-reuse` evidence directory:

- 34 compiled exact-key, invalid-proof and bound checks; two integrated native CPU identity/ABI tests.
- One actual native Metal test proves reacquire stability, changed source ID after raw slot-address/full-metadata reuse with different contents, cleared released/expired sidecars and no extra leases.
- 58 actual Mac Metal cache checks cover completed-only hits, changed display pose, bit-exact derived data, real readers blocked while another queue writes a replacement, pending/partial/abandoned commands, missing/foreign proof, source/queue/epoch changes, twelve-reader bound and both tall cached eye allocations within the byte cap.
- 58 assembled checks across 14 completed finite-sky plus gap-fill renders compare cached versus freshly generated preparation at seven display poses. RGB, Float32 depth and final ownership are byte-identical; six later draws hit the completed source cache. The fixture includes finite geometry, depth discontinuities and sky. Existing Metal shader code and its source-pixel triangle order are unchanged.
- Adjacent cacheless regressions pass: 68 budget checks, 44 actual Metal lifetime checks and 90 assembled checks across 18 renders.

An initial GPU test caught an admission defect: the second eye evicted the first eye's ready allocation even when there was room for both. Its failed result is retained. Admission now preserves the other eye until capacity pressure, and the same test passes. An independent first-party Claude Opus 5.5 source review and frozen admission follow-up found no correctness defect. Fast mode was requested, but the provider reported standard speed. Later small changes require an actual fresh native proof before pool access and preserve checkout set capacity; root review and the final tests cover these changes.

Two optional efficiency limits remain: a narrow gap between nominal and driver-padded allocation size may cause a needless fine fallback, and a never-requested old other-eye entry can remain bounded until eviction or epoch retirement. Neither permits a stale hit or busy overwrite. Test coverage is not physical gameplay, motion-to-photon, coherent stereo, FPS or perceived-quality acceptance. In particular, a six-hit synthetic fixture does not establish a useful real-game headset hit rate.
