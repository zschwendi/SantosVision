# Bind-group insertion and destruction invalidation, 2026-10-11

The opt-in bind-group preparation cache uses ordered shader/layout and resource identities in its key. `stage_bind_group` also resolves guest object IDs through texture, buffer, view, and sampler-state objects. A view may retain its guest ID while its referenced texture or buffer is created later; an earlier cached entry can therefore contain a native dummy binding under the same key. Replacing a live binding object with a nonbinding object has the reverse problem. Both transitions require a cache clear.

This candidate clears on `set_obj` if **either** the old or new object is a texture, buffer, SRV, UAV, or state containing a native sampler. `destroy` clears when the old object belongs to that set. Query, layout, shader, and state without a sampler do not affect the resolved bind-group resources, so insertion, replacement, or destruction entirely within that nonbinding set preserves the cache. The object match is exhaustive: a newly added object variant must receive an explicit binding-relevance decision. The feature-OFF path, world-depth invalidation, occlusion cleanup, guest object lifetime, complete ordered key, and per-call uniform snapshot stay as before.

The opt-in metrics now count avoided clears by operation and nonbinding object kind. These are source-site counts; they do not measure GPU time, frame rate, or memory savings. The existing Metal fixture was extended to require cache hits across unrelated nonbinding insertion/replacement/destroy and a miss when a live view is replaced by a nonbinding layout. It continues to require misses and actual buffer readback across same-view-ID replacement and missing-to-real buffer transitions. A pure test covers the relevance matrix and skipped-clear counters.
