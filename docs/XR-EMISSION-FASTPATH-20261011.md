# Opt-in XR emission mutex fast path

`MUGUET_XR_EMISSION_FASTPATH=1` enables a narrow producer-side shortcut in `xr_view::gpu_command`. It is default off. The existing VERSION5 game patch, ABI, GPU consumer, marker queue, and present handling are unchanged.

Each `SetCurrent` binding on a render thread gets a unique, monotonically increasing token, even when the view's matrices happen to be equal. The token is zero for no qualified view, an epoch reset, or exhausted token space. While the guest `wasm_gpu::Emit` producer mutex serializes emissions, a non-draw/non-present command with the same nonzero token as the immediately previous emission can skip the world-state mutex. Draws (opcode 32), presents (opcode 7), view transitions, unmatched/none views, and all correlation failures use the original locked `record_emission` path. The previous token is published only after that path has recorded the command and only if its view correlation remains valid. A session invalidation resets the previous token. Tokens are never recycled; exhaustion permanently disables the shortcut.

`world_view` status preserves `gpu_commands_marked` as the sum of locked and bypassed commands and adds `emission_mutex_commands`, `emission_fast_commands`, `emission_fastpath_enabled`, and `emission_token_exhausted`. Pure fixtures compare the ordered marker/present/conflict/epoch state against the legacy path across two producers, UI/none commands, repeated equal bindings, draws, presents, invalidation, and marker overrun. These fixtures are source-prepared and have not yet been compiled or run; the parent owns qualification and live timing. No FPS improvement is claimed.
