# Shared target game-camera mapping — manual third-person QA only

`MUGUET_COMPOSITOR_COMMON_TARGET_STAGE_QA=1` is a separate default-off experiment. It selects one newest qualified acquired source's `gameFromStage` for both target display eyes. Both genuine old eye rasters keep their own `gameFromEye`, source projection, depth, size and all source IDs. It does not create a same-update stereo pair, extrapolate a game camera to display time, alter source rendering, or change graphics/guard defaults. The frozen signed V27.5 package is separate and untouched.

The conditional issue is target-camera time, not incorrect source metadata. With source eye camera `S_i`, source stage mapping `G_i`, current head `H` and eye calibration `E_i`, the ordinary transform is `(G_i H E_i)^-1 S_i`. A static global world point therefore appears at stage point `G_i^-1 X`. Different `G_i` values can give the two eyes different target-stage positions. A common target `G*` instead gives both eyes `G*^-1 X`, while unprojecting each genuine source with its own camera/projection. Different source head/request generations alone do not cause this mismatch when their stage mappings agree.

The producer's mapping is approximately the native game camera times inverse reference-head pose. It carries all camera motion: follow, orbit/look, shake, vehicle chase and cuts. The legacy compositor corrects head motion while preserving each source's own game-camera time. This experiment adds game-camera reprojection to the older source. A moving avatar or chase vehicle can become less coherent even while the static background improves. Animation-time mismatch, occlusion and disocclusion remain. This is a trade-off to measure, not a demonstrated quality improvement or a proven cause of the user's physical flicker.

The registered `fixed-tp1440-idle-prevent` and `scene-fixture-repair/tall2304` airport capture pairs have identical mappings: the proposed mechanism is absent in those captures. Three supplemental native capture pairs show small mapping rotation differences (maximum about 0.0684°), but none is a completed M2/AVP display-pair observation. Pure CPU point tests demonstrate the conditional geometry only. This audit did not independently prove that the producer's pre-override native camera has no prior-override carry-over; selection uses its published, independently verified source mapping without changing that producer behavior.

## Gates and fallbacks

The experiment uses the exact same `opticalIndex` already selected for display optics. Both sources must be distinct actual eyes with valid immutable lease/game/request/head/camera IDs, matching nonzero view and retained-tracking epochs, and unscoped identity optics. Each retained request must pass the existing source-pose/projection verifier using that source's own mapping and carry the audited presentation-clock tag. The selected optical source must be newest by camera sequence, then game frame. Conflicting mappings under the same camera sequence are rejected.

All involved poses must be finite rigid transforms; projections must be finite invertible pinholes. Relative mapping deltas are evaluated in Double as `G*^-1 G_i`: stage-origin translation may not exceed 0.25 m and rotation may not exceed 5°. Translation measures the stage origin, including the reference-head rotation lever arm; it is not pure native camera translation. Actual target/source view displacement is additionally constrained by the ray-coverage gate. These conservative QA cut limits are not quality acceptance. Recenter clears retained poses and changes their tracking epoch; mismatched epochs or unavailable retained sources reject selection. There is no stored target or cross-frame selection state, so teardown, invalidation or missing sources cannot reuse an old mapping.

Coverage additionally requires each target frustum's four corner rays to remain inside the genuine source image with a 2% clip-space margin, both at target eye depth 5 cm and at infinity. Homogeneous side-plane inequalities then bound those pinhole rays at depths at least 5 cm. This is a source-frustum/ray bound, not proof that source geometry or unobscured background exists there. It may reject an otherwise bounded translation; the complete original per-eye path is the fallback. Source-anchor copy, analytic/synthetic probes, single-source diagnostics and native optical scopes retain their established paths.

Reticle code is unchanged. A visible V1 reticle uses per-source fallback mappings, so differing mappings reject common-target selection. A visible V2 reticle's common reference must agree with `G*`, otherwise selection is rejected. Agreement uses relative-pose bounds of 1 mm and 0.005°. Known first-person aim or an aim/source epoch mismatch rejects the experiment. Without a visible valid aim snapshot, reliable first-person/cockpit mode is not available to this selection; **the operator must manually keep the app in ordinary third person**. Unarmed first person, vehicle first person, ADS, scopes, weapons and Sense are outside this QA scope. This flag must never be a normal-play default.

`image_quality.common_target_stage_qa` records configuration. Sampled successful `completed_display_pairs[].target_stage` and the actual debug capture's separate `target_stage` metadata record applied/rejected status, reason, unchanged reticle policy, selected source IDs and target matrix bits. The debug capture's existing `game_from_stage` remains the genuine source mapping. Its recorded relative transform is exactly the one encoded, including a qualified target override. The `target_stage` key also appears when the flag is off, explicitly marked `requested:false` and `reason:not_requested`. Rejected decisions provide a reason; measured deltas are retained only for applied samples, and there are no per-frame rejection counters. Enable the existing completed-pair observer separately; neither flag enables the other. No per-frame JSON or file I/O was added. Enabled QA performs an additional retained-pose lookup per source per frame, so global retained-anchor hit/miss statistics are not comparable with baseline runs. Offline replay must use the exact recorded relative transform or the separate target matrix bits for applied captures; rebuilding it from source `game_from_stage` alone would be wrong.

## Controlled QA recipe

After the unchanged V27.5 physical comparison, use a separately built candidate and enable both `MUGUET_COMPOSITOR_COMMON_TARGET_STAGE_QA=1` and `MUGUET_COMPOSITOR_COMPLETED_PAIR_TELEMETRY=1` at launch. Keep normal source/graphics/guard settings, both genuine eyes, the same scene and source/cache configuration. Use the ordinary window-to-immersive route and manually confirm unarmed third person. First compare idle/no-change behavior, then orbit, walking and third-person driving separately. Compare background stability against the avatar/vehicle; record rejected gates, source ages, selected target source and camera deltas with any visible artifacts. An idle equal-mapping scene cannot demonstrate this experiment's benefit. No physical acceptance is claimed by CPU tests or source review.

`scripts/test-common-target-stage.sh` uses the exact production relative-transform calculation and pure production selection policy. It checks the default, unchanged equal-mapping case, static-point correction for changing translation/rotation, retained source cameras/IDs, newest optical selection, singular transforms, epochs, source kind, camera cuts, coverage, reticle incompatibility and stateless teardown. No GPU, device or simulator is executed.
