# Bind-group preparation experiment

`MUGUET_BIND_GROUP_PREPARE_OPT=1` enables a bounded stack key (32 `u64` words) and a bounded stack entry list (12 entries) in `stage_bind_group`. Longer keys and entry lists retain every element through a heap fallback. The normal cache key words, binding order, dynamic uniform offset, and native resource selection are unchanged. The default is OFF. The saved app choice **Reduce draw setup overhead (experimental)** also selects this path together with render preparation and direct uniform packing; an explicit diagnostic `1` or `0` overrides the saved choice for each path independently.

The complete resource walk still runs before lookup on every draw. It still packs a fresh constant-buffer snapshot, materializes pending clears, records texture and buffer use, and marks bound resources. A cache hit drops the temporary entry handles. A miss converts the temporary key and entries into owned vectors and creates the bind group. The opt-in path clears the bind-group cache when either the old or new object is a texture, buffer, SRV, UAV or sampler-bearing state. This covers both ID reuse and a previously missing resource becoming available behind an unchanged view ID; either transition can change the native binding without changing the lookup words. Changes entirely within query/layout/shader/non-sampler-state objects preserve the cache. The original cache size limit remains. The preceding app revision conservatively cleared on every successful insertion/destruction; the narrowed rule and its tests are documented in [BIND-GROUP-INVALIDATION-20261011.md](BIND-GROUP-INVALIDATION-20261011.md).

The `bind group prepare:` startup and ten-second log records lookup hits/misses, inline and spill lookups, owned key/entry materializations, invalidations, and sampled CPU wall time for one in 64 calls. These are source-site counters and timing samples, not allocator measurements or GPU timing. Native handle clones still occur in the resource walk on hits.

The helper tests compare complete ordered key words against the legacy `Vec<u64>` lookup, exercise heap fallback without truncation, and verify inline entry conversion. The Metal fixture checks two distinct dynamic uniform snapshots on a cache hit, reuses a guest view ID for another native buffer, then checks missing-to-real regular and counter-buffer bindings with fixed view IDs and GPU readback. The isolated candidate passed 112 full library tests. After integrating the saved control, the combined main tree passed **115 tests with all three paths OFF and 115 with all ON**, with zero failed, ignored or filtered. Source-bound receipt: `target/verification/reprojection-implementation-v1/draw-setup-controls/runs/native-tests-v2/receipt.json`, SHA256 `9d424bdacde0527345ca7228b3c449cfa20d7a92a30e4eb82157c0dbff731793`.

The first combined ON suite stopped at two uniform-fixture cache-UID assertions because those fixtures recreated objects between lookups. The test-only repair creates their constant buffers before the first dispatch and then mutates existing shadow bytes, preserving every exact cache-hit, dynamic-offset, staged-content and GPU readback assertion. The failed run remains in `native-tests-v1`. The fresh simulator and device apps built with the new typed startup bridge; actual-game qualification is recorded separately. No controlled FPS improvement or headset result is established by these tests.
