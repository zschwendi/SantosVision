# Optional host-only diagnostic scene fixture

`MUGUET_DIAGNOSTIC_SCENE=airport_clear_noon_v1` requests a disposable simulator performance fixture. With the variable absent, the `muguet_script` import behaves as before. An unknown ID is reported as `diagnostic_scene.request_error`; it never silently selects a different fixture.

The host invokes only exports already in the qualified VERSION5 `mp::COMMANDS` table after the existing `mp::script_tick` call. It uses the same documented script name, TLS slot, 2 KiB Emscripten scratch allocation, vector encoding, and hidden-output coordinate layout as `mp.rs`, restoring stack and TLS on normal and error paths. No guest WASM patch, AOT command map, camera mode, controller input, renderer, or launch setting changes. The selected `main_persistent` script pins the player ped at `(-1037, -2738, 13.8)` with heading 90 degrees, freezes it in place, sets 12:00:00 and persistent CLEAR weather, then reads position, heading, clock and weather hash back. These are virtual game coordinates; the location and exact live scene still require an isolated run to verify. Freezing the player and persistent weather deliberately alter simulation/lighting for diagnostics, not gameplay defaults. Traffic, streaming, and other independent game activity are not fixed.

`sv_runtime_status` exposes requested ID, script, target values, tick/application counts, latest readbacks, error, and `qualified`. Qualification requires ten consecutive successful readbacks at the fixed position (within 0.25 m), heading (within 1 degree), clock (12:00:00–01), and CLEAR weather hash. A missing script/ped, command trap, scratch failure, or mismatch leaves the fixture unqualified and reports the reason without hiding an ordinary runtime failure. The source is prepared only; no compile, native test, simulator run, image comparison, or timing has been performed. The diagnostic scene improves repeatability but is not a proof of identical per-frame draw workload.
