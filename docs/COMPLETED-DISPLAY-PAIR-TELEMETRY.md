# Completed display-pair density telemetry

This default-off observer adds `completed_display_pairs` under the existing image-quality runtime report. Enable the process launch environment `MUGUET_COMPOSITOR_COMPLETED_PAIR_TELEMETRY=1` before starting a new renderer. Omit it or use any other value to disable. It changes no source/display resolution, guard, graphics, draw order, resource lifetime, input, save or camera policy. It is separate from the frozen signed V27.5 comparison package and requires a future app build to run.

At most one eligible built-in two-eye drawable is sampled per second, and only the newest sixteen successful command completions remain in memory. Failed sampled commands and reserved samples that fail encoding/qualification increment separate counters. Capture stores immutable CPU values, without retaining a source texture or native lease. It performs no logging, JSON serialization or file I/O in render/command completion callbacks. Existing runtime-report reads create bounded dictionaries outside the collector lock; the existing report exporter owns serialization. The fixture with sixteen records is approximately 60 KB; actual integer lengths and optional fields vary.

Each successful record binds the compositor submission frame to two encoded, distinct actual source eyes from the same drawable and command buffer. Independent acquisition may select different game, request or head generations; those are retained per eye, never silently equated. `pair_acquired_atomically` distinguishes the native atomic-pair path. `native_acknowledged` additionally requires the completed presentation's ordered identities and acknowledged lease tokens to match this sample. A successful Metal command is not proof of physical scanout, stable motion, sharpness or visual acceptance.

The exact source projection, source game/eye and stage mappings, display projection and physical/world eye transforms, current source-to-eye transform and display head pose are retained as sixteen Float32 bit patterns in column-major order. Source size and the actual display viewport/density are retained per eye. The copy path additionally records its actual retained drawable anchor separately from the current display pose. Source matrices always come from the lease used to encode; retained request matrices never replace them.

`source_requested_guard_scale` is present only if the existing retained request passes `GameWorldSourcePoseCheck` against that eye's consumed request, source projection and source pose. Its provenance explicitly identifies that verification. If unavailable or mismatched, the reason is retained and the actual guard remains absent. `inferred_display_to_source_focal_ratio_xy` is a separately named slope comparison, affected by scoped display optics; it is not an asserted requested guard. It may remain available when the request has expired.

Timestamps remain separate: predicted display time from `LayerRenderer.Clock`, the unmodified native source presentation field, a successfully matched retained source-pose timestamp, copy-anchor timestamp when applicable, and completion-observed `ProcessInfo.systemUptime`. `predicted_display_clock` and each eye's `source_retained_pose_clock` explicitly identify their origins. Only when the source pose/projection is verified and both clocks name the audited `layer_renderer_presentation_epoch`, `source_pose_age_at_predicted_display_seconds` reports predicted display time minus that exact source's retained request-pose time. Both inputs and the difference must be finite. Negative/future and zero deltas are preserved without clamping. Unknown, mismatched or unverified origins omit the derived field. The retained request timestamp is itself the requesting drawable's predicted presentation target and its `queryDeviceAnchor` target. The derived value is therefore the difference between two predicted display targets tied to the matched source request, not elapsed time since a pose was sampled, native publication/queue latency or end-to-end motion latency. Native presentation, callback uptime and GPU times are never subtracted from pose timestamps. Callback order is retained; `compositor_frame` identifies submission order. No native/Swift clock calibration is implied.

`command_gpu_interval_seconds`, when available, is that same successfully completed command's `gpuEndTime - gpuStartTime`, requiring a finite positive start and finite end strictly greater than start. Invalid, zero, unavailable or failed-command timings never create an interval field. This is the whole command's overlapping GPU scheduling interval, including any other work encoded in it; it is not isolated shader busy time, FPS or display cadence.

## Retained timestamp producer audit

The detailed `XRHeadTracking.submit` method is the sole production constructor of `XRRetainedHeadPose` and sole caller of `retainLocked`. The timestamp domain defaults to `unknown` in both the submit API and the retained value, preserving other callers and test constructors. It is diagnostic metadata and never affects native submission, anchor lookup, expiry or rendering policy.

- `GameWorldRenderer` derives `timestamp` from `LayerRenderer.Clock.Instant.epoch.duration(to: drawable.frameTiming.presentationTime)`. Its detailed submit call explicitly tags this domain, and the same drawable timestamp tags the completed sample. The source lookup uses the lease's consumed head ID; existing verification matches its request ID, pose mappings and projection before any derived age is eligible.
- `CalibrationRenderer` derives the same presentation timestamp but uses the legacy non-retaining submit API; no retained entry is produced and it receives no inferred tag.
- `NativeRuntime`'s explicit simulator fixture supplies `ProcessInfo.systemUptime` through the legacy non-retaining API. It cannot produce an eligible retained pose. No simulator was run for this audit.
- Untracked game submissions and `XRHeadTracking.suspend` do not retain entries; suspend directly publishes an untracked uptime timestamp. Other future callers remain unknown unless explicitly tagged at an audited origin.

Per-eye `encoded_path` identifies the actual finite-sky, original, precomputed, adaptive or source-copy route. `ordered_preparation` is returned from the actual ordered preparation result: completed-source cache hit, fresh preparation, known ineligibility/unavailability, or finite-sky fallback reason. It is not derived by differencing global cache counters. The sampled retained-pose lookups increment the existing retained-anchor hit/miss statistics (about two lookups per second); do not treat those global counters as copy-path hit rate while telemetry is enabled. Preparation-unavailable is intentionally coarse and does not distinguish every allocator/encoder/cache-key failure. Resource pointers, cache keys and GPU rendering decisions are unchanged.

The legacy schema1 `sampling_density` array and depth-fill observer keys remain. Additive `sampling_density_stage` labels those older values as independent latest CPU observations without completion qualification. Do not compare a legacy per-eye value against a global lifecycle guard and call it one displayed pair.

## Controlled capture recipe

1. Keep the original27 rollback and signed V27.5 frozen package intact. Build this separately only after the unchanged27.5 headset comparison has completed. Install only under the parent's separately authorized device workflow, preserving saves/settings.
2. Enable the telemetry environment before app launch. Retain the same1440-line scene, source guard/freshness defaults and graphics settings. Follow the normal window-to-immersive route; require actual live gameplay and two distinct source eyes.
3. Run a short controlled turn/hold comparison. Retrieve the current own-app runtime report while this renderer/session is active so the sixteen-record ring is not replaced by a later inactive session. Compare cache off/on only with the separately specified ordered flags; this observer never enables them.
4. Inspect `completed_display_pairs.enabled`, `pairs`, per-eye identities/path, requested-guard provenance and matrix bits together. Preserve the raw report/session and configuration. A missing record means no eligible successful sampled stereo command; it is not a measured zero density. Approximately1Hz sampling can miss rapid flicker and does not replace the correlated latency trace or visual capture.
5. Remove the telemetry environment for ordinary use. No telemetry file or preference cleanup is needed.

## CPU verification

`scripts/test-completed-display-pair.sh` compiles the production collector and existing image-quality observer, then checks default-off behavior, one-second gating, unsuccessful and incomplete commands, duplicate/unordered eyes, independent generations, clock separation, qualified same-clock pose age including negative/future values, unknown/mismatched/nonfinite clock rejection, valid and unavailable completed GPU intervals, guard absence versus inference, exact matrix bits, actual per-eye preparation labels, bounded eviction, JSON compatibility, legacy keys and concurrent callback/report snapshots. It does not execute Metal.

Full physical-target visionOS Swift6 strict-concurrency typechecking and the existing CPU depth-edge-fill regression checks are separate checks. No app package, GPU render, simulator, device installation or physical acceptance is produced by this lane.
