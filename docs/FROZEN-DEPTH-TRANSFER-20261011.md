# Frozen pre-UI depth transfer

The app's saved **Reduce frame-copy overhead** choice, initially ON, lets the native world-frame bridge lease the depth texture that the GPU producer already copied immediately before GTA's recognized UI depth clear. The app configures the typed native setter before engine startup. Outside the app the default remains OFF; `MUGUET_TRANSFER_FROZEN_DEPTH=1` enables the diagnostic path and an explicit `0` disables it. Color is still copied into an immutable pooled texture, and the callback after GPU submission still gates publication. The existing depth copy remains the fallback for an ordinary depth proxy, a disabled choice, or a frozen candidate whose native handle, Metal device, dimensions, format or sampling/binding requirements do not match the selected source.

The producer wraps only the freshly allocated pre-UI snapshot as `FrozenPreUiDepth`. At present, it moves that candidate out of the depth map after the existing screen-ray, draw-count, full-size and unique-target checks. A newer qualified world draw removes the saved candidate; a mismatched or ambiguous present publishes nothing. No camera, projection, pair, source-epoch or compositor acknowledgement semantics change.

An accepted handoff skips one R32Float bridge copy: 31.640625 MiB for a 3840×2160 eye. The earlier pre-UI copy remains. The frozen texture becomes the pooled slot's sole depth texture. A free slot may replace its old depth only while its `Arc` has no pending submission, published frame or compositor lease; a new slot allocates color but adopts the frozen depth without allocating another depth image. Each of the six bounded slots therefore still owns one color and one depth texture. `world_frames.frozen_depth_handoffs` and `world_frames.copied_depth_snapshots` count GPU-complete publications for the two paths.
